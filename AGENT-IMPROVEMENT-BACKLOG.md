# Backlog улучшений агента

Это единственный журнал согласованных изменений agent-layer. Он не является
входом practical route и не содержит задач по конкретному FT-scope. Для каждой
записи указаны источник, приоритет и условие завершения; идеи без наблюдаемой
причины сюда не добавляются.

Приоритеты: `P1` — исправить до следующего затронутого practical запуска;
`P2` — планировать после текущего выпуска тест-кейсов; `P3` — legacy-долг или
исследование, не блокирующее practical v0.9.

Правило ведения: если по итогам проверки вместо немедленного изменения
предлагается улучшение agent-layer, оно добавляется в этот backlog в той же
итерации с наблюдаемым основанием и критерием завершения. Исключение — идея
без подтверждённой причины; её не представляют как согласованную работу.

## Незакрытые улучшения practical v0.9

- [ ] `AGI-014` (`P2`) Разделить совместимость source package manifest и
  версию запускающего инструмента.
  - Основание: повторная materialization scope `9.3.2` получила единственное
    transport-warning только потому, что source manifest создан v0.9.7, хотя
    структура и хеши входов совместимы с v0.9.8.
  - Завершено, когда: validator предупреждает только о несовместимой schema
    или изменившихся source inputs; безопасное обновление agent-layer без
    изменения source package не создаёт шумного warning.

- [x] `AGI-015` (`P2`) Не оставлять устаревшую status-проекцию workflow после
  принятого matrix re-review или выпуска TC.
  - Основание: в scope `9.3.2` после verdict `approved` и перехода к
    `phase: test-cases` поле `final_verdict` осталось `changes-required` от
    предыдущего matrix review, а после выпуска TC `next_action` продолжает
    говорить «Написать тест-кейсы»; это вводит в заблуждение человека и
    статусный renderer.
  - Завершено, когда: `final_verdict` описывает только final TC review, а
    результат matrix review хранится в `reviews`; `next_action` отражает
    фактическую следующую фазу; переходы и renderer не показывают устаревший
    verdict как финальный.
  - Выполнено: `final_verdict` нормализуется и относится только к final TC
    review; после matrix approval он сбрасывается в `not-finalized`. После
    записи TC workflow обязан перейти в `phase: review`; validator выявляет
    оставшийся writer-phase. Добавлены migration и transition regressions.

- [x] `AGI-016` (`P1`) Добавить practical writer-gate для исполнимости
  тестовых данных и полноты trigger-шагов.
  - Основание: в первом выпуске TC scope `9.3.2` восемь кейсов содержат
    тавтологичное «Данные, предусмотренные проверяемым правилом», а два кейса
    про второй файл не имеют отдельного шага прикрепления первого файла.
    Scoped validator не выявил эти дефекты.
  - Завершено, когда: practical v0.9 требует в поле «Тестовые данные» либо
    конкретные literals/значения, либо точные свойства и способ подготовки
    отсутствующего набора; запрещает пересказ правила как данные; все
    действия, создающие состояние trigger, перечислены отдельными шагами.
    Добавлены узкие validator-regressions и проверка reviewer-ом на реальном
    scope.
  - Выполнено: scoped validator v0.9.11 блокирует tautological test data и
    неполный trigger для явного ограничения «не более одного файла»; правило
    закреплено в canonical route и practical skill, добавлены regression tests.

- [x] `AGI-017` (`P1`) Разделить бюджеты содержательных доработок matrix и
  canonical TC.
  - Основание: scope `9.3.2` израсходовал общий `revision_count` на matrix
    finding MR-001. В `finalize_practical_review.py` следующий blocking finding
    final TC review при `revision_count >= 1` сразу переводит scope в `blocked`,
    хотя practical route требует одну целевую TC-доработку после final review.
  - Завершено, когда: matrix review имеет не более одной собственной
    matrix-доработки и re-review, final TC review — не более одной собственной
    TC-доработки и fresh final review; workflow migration, validator, renderer
    и regression tests исключают новый repair-loop и не блокируют TC-revision
    только потому, что ранее исправлялась matrix.
  - Выполнено: `matrix_revision_count` и `tc_revision_count` имеют независимые
    лимиты; legacy `revision_count` мигрируется детерминированно по истории
    review при следующем чтении/финализации. Добавлены regression tests для
    миграции, первого TC finding после matrix revision и второго TC finding.

- [x] `AGI-018` (`P1`) Убрать лексическую зависимость validator-а от слов
  «первый» и «второй» при проверке ограничения на один прикрепляемый файл.
  - Основание: при writer-доработке scope `9.3.2` шаги «прикрепить
    `решение-1.pdf`» и «попытаться прикрепить `решение-2.pdf`» уже однозначно
    задавали начальное состояние и вторую попытку. Validator ошибочно выдал
    два blocking finding только из-за отсутствия буквально слова «второй».
    Агенту пришлось менять формулировку без изменения проверки.
  - Завершено, когда: validator распознаёт две упорядоченные самостоятельные
    операции прикрепления с различающимися файлами без требования порядковых
    слов; регрессии покрывают вариант с явными «первый/второй», вариант с
    разными именами файлов без этих слов и отрицательный случай без начального
    прикрепления.
  - Выполнено: validator сопоставляет самостоятельные операции по их порядку
    и различающимся идентификаторам файлов; добавлены оба положительных
    варианта и отрицательная регрессия без начального прикрепления.

- [x] `AGI-019` (`P1`) Ввести самостоятельный уровень test-design-сценария
  для нескольких атомарных проверок одного правила в одном контексте.
  - Основание: final TC review scope `9.3.2` выявил, что правило «размер файла
    не превышает 40 МБ» требует как минимум двух независимых проверок:
    приём файла ровно 40 МБ и отклонение файла 40 МБ + 1 байт. Жёсткое правило
    «одна пара OBL/CTX — один TC» не допускает второй атомарный TC без
    искусственного разбиения source obligation.
  - Завершено, когда: matrix поддерживает явные сценарии (`SCN-*`) с общей
    OBL/CTX и разными проверяемыми классами/границами; каждый SCN имеет ровно
    один TC и один основной oracle. Validator по-прежнему запрещает дубли,
    но допускает несколько TC для OBL/CTX только при разных declared SCN.
    Регрессии покрывают включённую и исключённую границы одного ограничения.
  - Выполнено: в matrix введён обязательный уникальный `SCN-*`; validator
    требует ровно один canonical TC для каждого SCN и проверяет его
    OBL/CTX, планируемый TC-ID и статус. Несколько сценариев одного OBL/CTX
    допустимы только как разные SCN.

- [x] `AGI-020` (`P1`) Сделать contract формирования состояния общим для
  practical writer, а не только для ограничения числа upload-файлов.
  - Основание: final TC review scope `9.3.2`, finding F-001 и F-006: ряд TC
    не содержит самостоятельных шагов формирования поиска DaData, пустого
    обязательного поля, дубля, несохранённого изменения или повторного
    наблюдения отсутствия сохранения. Формально зелёный scoped validator это
    не выявил, потому что его state-trigger gate пока узок и upload-specific.
  - Завершено, когда: matrix и writer обязаны явно различать исходное
    состояние, шаг его формирования, проверяемое действие и наблюдаемый
    oracle; validator проверяет этот contract для воспроизводимых категорий
    (поиск/выбор, required, duplicate, отмена/закрытие, отсутствие
    сохранения). Ненаблюдаемое
    внутреннее действие без самостоятельного oracle классифицируется как
    `blocked-observability`. Regression tests подтверждают, что пропуск setup
    или follow-up observation блокирует маршрут, а полноценный сценарий
    проходит.
  - Выполнено: matrix получила обязательные поля «Исходное состояние»,
    «Формирование состояния» и «Проверяемое действие»; validator проверяет
    явные trigger/follow-up шаги для DaData, required, duplicate и отмены
    сохранения. Внутреннее ненаблюдаемое действие требует
    `blocked-observability`.

- [x] `AGI-021` (`P1`) Сохранять дословное ожидаемое сообщение, когда ФТ
  содержит его literal.
  - Основание: final TC review scope `9.3.2`, finding F-004: OBL-042 содержит
    точный текст ошибки при недопустимом файле, но matrix и TC заменили его
    общим ожиданием «выводится сообщение об ошибке». Это теряет проверяемую
    часть требования при формально сохранённой трассировке.
  - Завершено, когда: writer переносит source literal в ожидаемый результат
    без перефразирования, а validator выявляет TC, где OBL с обязательной
    цитатой сообщения не имеет этой цитаты в oracle. Regression tests
    покрывают точное совпадение, отсутствующий literal и несвязанную цитату.
  - Выполнено: source-литералы в кавычках распознаются только при контексте
    наблюдаемого сообщения; validator требует их точного переноса в oracle
    matrix и canonical TC. Добавлены узкие регрессии для совпадения,
    отсутствующего literal и несвязанной цитаты.
