# Backlog улучшений агента

- [x] `AGI-046` (`P1`) Связывать обязательность сохранения в сценарии дубля с действием matrix, а не с наличием слова «существующий» в требовании.
  - Основание: writer scope `9.3.2` был остановлен двумя ложными блокерами validator-а для AS.5: ФТ требует подсказку и переход сразу после ввода существующего названия, но validator требовал «СОХРАНИТЬ».
  - Выполнено: правило `test-case-duplicate-trigger` применяется только если у связанной строки matrix проверяемое действие — сохранение; сценарии подсказки/перехода при вводе остаются без искусственного шага сохранения. Добавлена регрессия для обоих потоков.

- [x] `AGI-045` (`P1`) Не объявлять противоречием требования с разными действиями или моментами проверки.
  - Основание: при анализе чистого scope `9.3.2` агент временно посчитал AS.5 и AS.37 противоречивыми, хотя AS.5 описывает реакцию при вводе/выборе, а AS.37 — результат сохранения.
  - Выполнено: practical route требует до объявления blocker сопоставить объект, действие, момент, условие и результат; при различии действия или момента требования остаются отдельными `OBL-*`/`CTX-*` без CLR и blocker.

- [x] `AGI-044` (`P1`) Не дробить один составной UI-результат по полям карточки.
  - Основание: scope `9.3.2` разложил выбор подсказки DaData на отдельные TC
    автозаполнения наименования, адреса, ИНН, ОГРН и КПП, хотя это один
    пользовательский action и один наблюдаемый механизм. Та же проблема
    применима к однотипной редактируемости полей карточки.
  - Выполнено: `scenario_consolidation` допускает узкий basis «поля одного
    составного результата» только при одном контексте, механизме, действии,
    исходном состоянии, типе и статусе. Он требует полный `field_inventory`,
    `composite_result` и таблицу всех полей в TC; отдельные validation,
    UI-уровни, save-эффекты и самостоятельные реакции по-прежнему разделяются.

- [x] `AGI-043` (`P1`) Блокировать общие и неисполняемые тестовые данные.
  - Основание: повторный independent final TC review scope `9.3.2` обнаружил
    общие формулировки «остальные обязательные поля заполнить допустимо» и
    «уникальный набор обязательных значений», а также границы строк и файлы
    без воспроизводимого способа подготовки. Scoped validator их не увидел.
  - Выполнено: validator отклоняет общую completion-формулировку, действие в
    разделе «Тестовые данные» и граничную строку/подготовленный файл без
    `Способ подготовки`. Practical route требует полный `DICT-*` inventory и
    ожидание «ровно этот набор, иных нет» для закрытого справочника; добавлены
    положительные и отрицательные регрессии.

- [x] `AGI-042` (`P1`) Формально проверять статусные findings reviewer-а.
  - Основание: final TC reviewer scope `9.3.2` потребовал сменить `needs-test-data` на `candidate-ui-calibration`, хотя полная цепочка `SETUP-*` также не подготовлена. Finding не содержал `status_assertion`, поэтому controller ошибочно принял рекомендацию.
  - Выполнено: reviewer обязан приложить `status_assertion` для требования смены статуса; controller не принимает его, если целевой статус расходится с вычисленным приоритетом всех предпосылок.

Это единственный журнал согласованных изменений agent-layer. Он не является
входом practical route и не содержит задач по конкретному FT-scope. Для каждой
записи указаны источник, приоритет и условие завершения; идеи без наблюдаемой
причины сюда не добавляются.

Приоритеты: `P1` — исправить до следующего затронутого practical запуска;
`P2` — планировать после текущего выпуска тест-кейсов; `P3` — legacy-долг или
исследование, не блокирующее practical v0.9.

Правило ведения: если по итогам проверки вместо немедленного изменения
предлагается улучшение agent-layer, оно добавляется в этот backlog в той же
итерации с наблюдаемым основанием и критерием завершения. Исключение — идея
без подтверждённой причины; её не представляют как согласованную работу.
