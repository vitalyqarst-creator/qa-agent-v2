# FT Source Locator

Используй только для регистрации входных материалов. До чтения FT-пакета прочитай `references/runtime/session-topology.md` и `references/runtime/source-selection.md`, затем проверь controller-owned registry командой `runtime_session_registry.py verify --through source-locator --expected-role source-locator --expected-thread-id <own-threadId>`. При ошибке остановись.

1. Проверь `AGENT-NOTES.md` в корне FT-пакета и прочитай его. Без файла остановись как `blocked-input`.
2. Выбери один канонический источник ФТ (`semantic_primary`). Обеспечь одно нормализованное XML/XHTML-представление (`machine_readable_primary`): если канонический файл — DOCX и готового представления нет, создай его командой `python scripts/normalize_ft_source.py <source.docx> <source.normalized.xhtml>` и добавь производный файл в классификацию `AGENT-NOTES.md`; проверь в результате сохранность таблиц, строк и видимых автонумерованных меток Word (кодов требований, подписей таблиц и пунктов). Если нативный XHTML одновременно является каноническим, зарегистрируй обе роли в одной записи через `semantic_primary+machine_readable_primary`. Не требуй от пользователя три копии одного ФТ.
3. Определи необходимость визуальной сверки. Установи `visual_crosscheck: required`, если смысл зависит от рисунков, сложной табличной разметки, объединённых ячеек или расположения элементов, и зарегистрируй PDF/рендер с ролью `visual_structural_crosscheck_only`. Иначе установи `visual_crosscheck: not_required` и запиши конкретную `visual_crosscheck_reason`; отсутствие PDF само по себе не блокирует этап.
4. Зарегистрируй support-файлы, словари, макеты и Figma-ссылки с их ролями. На source-этапе не выполняй полный семантический анализ support и не загружай целиком объёмные справочники: используй классификацию из `AGENT-NOTES.md`, имя/формат файла и при необходимости только заголовки или небольшой начальный фрагмент. Полное чтение относящегося к scope support выполняет scope analyzer. Роль и приоритет, явно заданные в `AGENT-NOTES.md`, обязательны и не понижаются из-за возраста файла или упоминания старого процесса внутри него. Старые рабочие папки не являются состоянием текущего процесса, но извлечённые из них утверждённые ответы остаются действующим входом, если так указано в `AGENT-NOTES.md`. Макет/Figma — только visual input.
5. Запиши компактный русскоязычный `source-selection.md` и `workflow-state.yaml` версии `source_contract_version: 2` в `work/stage-handoffs/00-<ft>/`. Для машинного представления укажи `origin: canonical|generated|supplied`; для generated дополнительно укажи `derived_from`, `derived_from_sha256` и `generator`. Пути, SHA-256, URL и имена файлов сохраняй без перевода.
6. Временные рендеры создавай только в отдельном системном временном каталоге с именем `ft-runtime-<назначение>-<случайный-id>`. После просмотра очищай только этот точный каталог командой `python scripts/cleanup_runtime_temp.py <absolute-temp-path>`; не составляй рекурсивный `Remove-Item`/`rm` вручную. Затем обязательно запусти `python scripts/validate_runtime_source.py <package-root> <source-handoff-dir>`. Используй документированную команду и её результат, не читай реализацию validator-а без фактической ошибки, требующей диагностики. Без `valid=true` этап не завершён.

Если пользователь добавил support-файл после появления вопросов или downstream-артефактов, повторно используй ту же source-locator-сессию и выполни только регистрацию позднего support: добавь файл с точной ролью и SHA-256 в существующие `AGENT-NOTES.md`, `source-selection.md` и `workflow-state.yaml`, не перечитывая и не переанализируя primary sources. Для такой ограниченной операции запусти `python scripts/validate_runtime_source.py <package-root> <source-handoff-dir> --support-update`. Этот режим не разрешает пропускать новый support-файл и не создаёт новый source stage; он лишь не считает уже существующие scope/matrix/TC ошибкой source locator-а.

Если controller возобновляет новый practical route на существующем пакете без новых inputs, source locator не запускается повторно. Существующий выбор источников проверяется controller-ом через `--resume-existing`; эта проверка не является semantic stage.

Не создавай scope, matrix, fixtures, вопросы БА или TC.
