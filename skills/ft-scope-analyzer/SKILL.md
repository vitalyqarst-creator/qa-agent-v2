# FT Scope Analyzer

## Вход и запуск

1. Выполни registry self-check для роли `scope-analyzer`. `AGENTS.md` уже загружен средой: не перечитывай его. `session-topology.md` относится к controller и анализатору не нужен.
2. Прочитай этот skill и `references/runtime/scope-analysis.md`. `references/runtime/test-data-fixtures.md` открывай только если активные обязанности требуют конкретных значений, справочника, интеграции, границ или подготовки состояния.
3. До записи артефактов получи точный публичный контракт:

   `python -X utf8 scripts/validate_runtime_scope.py --print-contract --scope <scope>`

   Копируй показанные Markdown-шаблоны целиком, включая строку-разделитель; не собирай таблицы по памяти. Используй показанные форматы ID, обязательные файлы и заголовки. Реализацию validator-а заранее не читай.

## Анализ

Подтверди границы одного раздела по каноническому и нормализованному источникам. Прочитай выбранный раздел целиком. Родительский вводный/завершающий текст анализируй только если он нормативен; распределяй его по явно названным областям, не присваивай автоматически первой области.

Создай в `work/stage-handoffs/<canonical-scope>/`:

- `source-row-inventory.md` — атомарные `SR-*` и контракт проверяемости;
- `scope-brief.md` — границы и только применимые проверки;
- `coverage-gaps.md` — source-level недостатки;
- `test-data-plan.md` — логические роли данных, допустимые источники, отношения и воспроизводимая подготовка;
- `prompt.scope-to-writer.md` и `workflow-state.yaml`.

Обнови единый `work/scope-clarification-requests.md`; локальную копию не создавай.

Один `SR-*` описывает один объект/UI-уровень, условие, действие и наблюдаемый результат. Составное утверждение разложи; GAP относится только к неизвестному остатку. Код требования сохраняй дословно, а без кода используй точную строку таблицы либо раздел с короткой цитатой. Контекст без самостоятельного результата не превращай в `SR-*`.

Если источник не задаёт необходимый бизнес-результат, роль, точку наблюдения либо противоречит другому утверждённому источнику, создай отдельный `GAP-*`. Точный source anchor из `SR-*` копируй в GAP и вопрос без перефразирования. Отсутствие стендового объекта, логина, URL или доступа отражай только в плане данных.

Перед новым вопросом ищи ответ по anchor в общем реестре и утверждённых support-файлах. Нерешённый вопрос получает статус `ожидает-ответа` и строку `**Ответ БА:** _Введите ответ здесь._`; отвеченную карточку обновляй, не удаляй.

В плане данных не получай внешние ответы и не подбирай случайные записи. Для каждой целевой и prerequisite-сущности создай `TD-*` с источником, обязательными полями, отношениями и изоляцией. Источник provider/dictionary-bound сущности наследуется и в чужом scope. Точные значения появятся после принятия matrix.

Для каждой используемой таблицы сверь все строки XHTML. У активной строки отдельно отрази обязательность, редактируемость, тип/класс ввода и применимое примечание; anchor строки не доказывает полноту. Короткие заголовки трактуй только по явной легенде. Для каждого включённого UI-уровня сверь релевантный макет. Сравнивай видимые подписи буквально; нерелевантные визуальные входы не перечисляй. Figma открывай один раз лишь при недостатке локального evidence.

В `Проверку согласованности` включай только применимые аспекты из canonical reference. Не создавай строки `Не применимо` ради полноты шаблона.

Один содержательный проход — default. Целевую повторную сверку выполняй только по сигналам сложности из canonical reference и только по соответствующему риску.

## Завершение

Не создавай matrix, TC, debug-инвентари и технические транскрипты. Все человекочитаемые поля пиши на русском.

Запусти:

`python -X utf8 scripts/validate_runtime_scope.py <package-root> <scope-handoff-dir>`

В initial `workflow-state.yaml` установи `scope_revision_count: 0`. При ошибке используй `error_counts_by_class`: не называй сбой форматным, если validator вернул иные классы. Если `correction_allowed=true`, перед локальным исправлением установи `scope_revision_count: 1`, исправь только перечисленные причины и запусти validator ещё раз. При повторном `valid=false` не выполняй третью попытку и верни controller-у остановку по лимиту. Передача writer-у разрешена только при `valid=true`.
