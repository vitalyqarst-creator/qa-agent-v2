# FT Scope Analyzer

## Вход и запуск

1. Выполни registry self-check для `scope-analyzer`. `AGENTS.md` уже загружен средой: не перечитывай. `session-topology.md` не нужен.
2. Прочитай этот skill и `references/runtime/scope-analysis.md`. `references/runtime/test-data-fixtures.md` открывай только если активные обязанности требуют конкретных значений, справочника, интеграции, границ или подготовки состояния.
3. До записи артефактов получи точный публичный контракт:

   `python -X utf8 scripts/validate_runtime_scope.py <package-root> --print-contract --scope <scope>`

   Копируй Markdown-шаблоны целиком; не собирай их по памяти. Заголовки и названия строк бери из `source_table_catalog`; свойства — из XHTML. Сверь `selected_requirement_catalog`, `parent_intro_requirement_catalog` и `incoming_action_catalog`: каждый элемент получает SR/GAP, исключение или ownership-решение. Используй conditional contracts. Реализацию validator-а не читай.

## Анализ

Используй зарегистрированный XHTML как рабочую поверхность. Не перечитывай весь DOCX/PDF и не подключай общие document/PDF-навыки: обращайся к каноническому файлу точечно только при неоднозначности XHTML или отмеченном source-различии. Для UI сначала используй релевантный локальный макет. Прочитай выбранный раздел целиком; нормативный родительский текст распределяй по явно названным областям.

Создай в `work/stage-handoffs/<canonical-scope>/`:

- `source-row-inventory.md` — атомарные `SR-*` и контракт проверяемости;
- `scope-brief.md` — границы и только применимые проверки;
- `coverage-gaps.md` — source-level недостатки;
- `test-data-plan.md` — логические роли данных, допустимые источники, отношения и воспроизводимая подготовка;
- `prompt.scope-to-writer.md` и `workflow-state.yaml`.

Обнови единый `work/scope-clarification-requests.md`; без локальной копии.

Один `SR-*` описывает один объект/UI-уровень, условие, действие и результат. Успешный результат и отказ/ошибку разделяй; невалидные классы с одинаковым отказом можно параметризовать. Альтернативные ключи/способы ввода фиксируй отдельными классами, не как «A или B». Для обязательного системно заполненного read-only поля не выдумывай путь к пустому состоянию: покрывай заполнение и недоступность редактирования либо фиксируй недостижимость. GAP относится только к неизвестному остатку. Контекст без самостоятельного результата не превращай в `SR-*`.

Если источник не задаёт необходимый бизнес-результат, роль, точку наблюдения либо противоречит другому утверждённому источнику, создай отдельный `GAP-*`. Точный source anchor из `SR-*` копируй в GAP и вопрос без перефразирования. Отсутствие стендового объекта, логина, URL или доступа отражай только в плане данных.

Перед GAP `нет-точки-наблюдения` выполни bounded closure supporting execution anchors по `references/runtime/scope-analysis.md`; недоступная Figma сама по себе не blocker.

Перед новым вопросом ищи ответ по anchor в общем реестре и утверждённых support-файлах. Нерешённый вопрос получает статус `ожидает-ответа` и строку `**Ответ БА:** _Введите ответ здесь._`; отвеченную карточку обновляй, не удаляй.

В плане данных не получай значения. Задай минимальный baseline `TD-*`, источников, отношений и изоляции; для каждой сущности наследуй provider/справочник её создания. При наличии принятых materialization других scope один раз запусти `runtime_fixture_candidates.py` и укажи совместимый scope как сохранённый источник, не копируя литералы. Стенд и его изменяемые статусы/роли — подготовка и `needs-test-data`, не источник идентичности. URL, логин, credentials и общий доступ не являются `TD-*`; если иных данных нет, напиши `Данные не требуются.`. Writer расширит план после matrix.

Сверь используемые и родительские/контейнерные таблицы XHTML по `scope-analysis.md`. Короткие заголовки требуют легенды. Сравнивай видимые подписи буквально; для включённого UI-уровня сверь релевантный макет; нерелевантные визуальные входы не перечисляй, Figma открывай лишь при недостатке локального материала.

В `Проверку согласованности` включай только применимые аспекты из canonical reference. Не создавай строки `Не применимо` ради полноты шаблона.

Таблицу зависимых результатов создавай только для фактической причинности по `scope-analysis.md`; общий source anchor причинность не доказывает.

Один содержательный проход — default. Повторная сверка — по сигналу сложности и риску.

## Завершение

Не создавай matrix, TC, debug-инвентари и транскрипты. Человекочитаемые поля — на русском.

Запусти:

`python -X utf8 scripts/validate_runtime_scope.py <package-root> <scope-handoff-dir>`

В initial `workflow-state.yaml` установи `scope_revision_count: 0`, `status: draft`; итоговый status ставит validator. Следуй только его correction-флагам и исправляй перечисленные ошибки. Count `4` сохраняй при `validator_repair_allowed=true`; этот режим восстанавливает ошибочно закрытый количественный GAP и pending-clarification. Полная политика — в `references/runtime/scope-analysis.md`. После изменения `SR-*`/`GAP-*` обнови все ссылки. Передача разрешена только при `writer_allowed=true` и `workflow_status=completed`.
