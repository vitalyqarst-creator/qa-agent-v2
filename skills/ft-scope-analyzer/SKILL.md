# FT Scope Analyzer

## Вход и запуск

1. Выполни registry self-check для роли `scope-analyzer`. `AGENTS.md` уже загружен средой: не перечитывай его. `session-topology.md` относится к controller и анализатору не нужен.
2. Прочитай этот skill и `references/runtime/scope-analysis.md`. `references/runtime/test-data-fixtures.md` открывай только если активные обязанности требуют конкретных значений, справочника, интеграции, границ или подготовки состояния.
3. До записи артефактов получи точный публичный контракт:

   `python scripts/validate_runtime_scope.py --print-contract --scope <scope>`

   Используй показанные форматы ID, обязательные файлы и заголовки. Реализацию validator-а заранее не читай.

## Анализ

Подтверди границы одного раздела по каноническому и нормализованному источникам. Прочитай выбранный раздел целиком. Родительский вводный/завершающий текст анализируй только если он нормативен; распределяй его по явно названным областям, не присваивай автоматически первой области.

Создай в `work/stage-handoffs/<canonical-scope>/`:

- `source-row-inventory.md` — атомарные `SR-*` и контракт проверяемости;
- `scope-brief.md` — границы и только применимые проверки;
- `coverage-gaps.md` — source-level недостатки;
- `test-data-plan.md` — источники и воспроизводимая подготовка;
- `prompt.scope-to-writer.md` и `workflow-state.yaml`.

Обнови единый `work/scope-clarification-requests.md`; локальную копию не создавай.

Один `SR-*` описывает один объект/UI-уровень, актора и условие, действие/событие и один наблюдаемый результат. Сохраняй код требования любого формата дословно; без кода используй точную строку таблицы или раздел с короткой цитатой. Для таблицы указывай номер и точный текст строки первого столбца. Независимые свойства строки разделяй. Определение или контекст без самостоятельного наблюдаемого результата не превращай в `SR-*`.

Если источник не задаёт необходимый бизнес-результат, роль, точку наблюдения либо противоречит другому утверждённому источнику, создай отдельный `GAP-*`. Точный source anchor из `SR-*` копируй в GAP и вопрос без перефразирования. Отсутствие стендового объекта, логина, URL или доступа отражай только в плане данных.

Перед новым вопросом ищи ответ по anchor в общем реестре и утверждённых support-файлах. Нерешённый вопрос получает статус `ожидает-ответа` и строку `**Ответ БА:** _Введите ответ здесь._`; отвеченную карточку обновляй, не удаляй.

Для каждой используемой таблицы выполни контроль всех её строк по XHTML. Семантику коротких заголовков фиксируй только по явной легенде; без неё создай GAP. Для каждого включённого UI-уровня сверь релевантный зарегистрированный макет. Сравнивай видимые подписи буквально: различие между ФТ и макетом фиксируй как различие, а не как согласованность. Figma открывай один раз только если локального evidence недостаточно; нерелевантные визуальные входы не перечисляй.

В `Проверку согласованности` включай только применимые аспекты из canonical reference. Не создавай строки `Не применимо` ради полноты шаблона.

Один содержательный проход — default. Выполни целевую повторную сверку только если есть хотя бы один сигнал сложности: нормативный родительский текст; более одной активной таблицы или UI-поверхности; cross-scope ссылка; support override/противоречие; десять и более `SR-*`. Повторная сверка касается только соответствующего риска.

## Завершение

Не создавай matrix, TC, debug-инвентари и технические транскрипты. Все человекочитаемые поля пиши на русском.

Запусти:

`python scripts/validate_runtime_scope.py <package-root> <scope-handoff-dir>`

При ошибке открой только названный контракт и исправь его одним локальным проходом. Передача writer-у разрешена только при `valid=true`.
