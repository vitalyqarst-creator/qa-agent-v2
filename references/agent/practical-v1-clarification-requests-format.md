# Формат вопросов БА для practical v1

`scope-clarification-requests.md` — единственный рабочий документ scope для
вопросов БА и его ответов. Он всегда создаётся до матрицы. Если вопросов нет,
в нём остаётся явная строка `Вопросов к БА не выявлено`.

## Карточка вопроса

Каждый вопрос имеет стабильный идентификатор `BAQ-<scope>-<номер>` и содержит:

```md
### BAQ-<scope>-001 — краткая тема

- **Источник:** раздел, код требования, таблица/строка или поле.
- **Вопрос:** самодостаточный вопрос на русском языке.
- **Почему это влияет на тест:** какой ожидаемый результат, ветка или
  применимость проверки изменится после ответа.
- **Область применения ответа:** точные требования, поля или сценарии.
- **Статус:** `open`
- **Ответ БА:** _[заполняется БА]_
- **Решение для тест-дизайна:** _[заполняет агент после анализа ответа]_
```

БА заполняет только поле **«Ответ БА»**. После непустого ответа агент меняет
`Статус` на `answered` и заполняет **«Решение для тест-дизайна»**. Не добавляй
поля даты, источника ответа, роли автора или отдельный реестр ради одного
scope-local ответа: история изменения файла уже доступна в Git.

## Сохранение ручных ответов

- При повторном scope-анализе агент сохраняет текст **«Ответ БА»** дословно.
- Если вопрос устарел, не затирай ответ: пометь `Статус` как `superseded` и
  создай новый `BAQ-*` с явной ссылкой на предыдущий.
- Использовать в matrix и TC можно только ответ со `Статус: answered`.
- Package-wide утверждённое решение, применимое к нескольким scope, после
  использования можно перенести в `support/approved-ba-decisions.md` со
  ссылкой на исходный `BAQ-*`; этот перенос не обязателен для продолжения
  текущего scope.

## Границы

Вопрос БА создаётся только для продуктовой неоднозначности. Не спрашивай БА о
URL, логинах, конкретной учётной записи, fixture, способе подготовки данных
или неподтверждённой UI-детали: это `needs-test-data`,
`candidate-ui-calibration` либо `blocked-observability` в соответствующей
matrix-строке.
