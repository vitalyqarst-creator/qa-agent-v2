# Runtime Quality Rule Cards

| rule_id | trigger | required action | validator gate |
|---|---|---|---|
| R-CANDIDATE-NEG | visible source-backed input restriction, missing UI rejection oracle | write candidate-negative TC with concrete invalid value; BA gap may accompany, not replace | `source-backed-input-restriction-gap-only`, `test-case-ui-calibration-candidate-missing-concrete-invalid-value` |
| R-ROLLING-DATE | current/future/not-later-than-current/relative date | use `D`; fixed date only as example; define `D`, format and example for relative values | `rolling-date-boundary-static-test-data`, `rolling-date-boundary-unformalized-relative-value` |
| R-ATOMICITY | TC traces >2 independent `ATOM`/`BSR`/`GSR`/`REQ` obligations | split, or justify one source-backed workflow via `Сценарное обоснование` with atomic coverage elsewhere | `test-case-overmerged-atoms-without-rationale`, `test-case-excessive-atom-fan-in` |
| R-SCENARIO-RATIONALE | grouped/source-backed TC | canonical `**Сценарное обоснование:**`; name target/source rows; match exercised stimulus | `scenario-rationale-noncanonical-field`, `scenario-rationale-domain-mismatch`, `scenario-rationale-too-generic`, `scenario-rationale-stimulus-mismatch` |
| R-REPRESENTATIVE | sampled similar fields/classes | document strategy, selected/omitted combinations and residual risk | `missing-representative-strategy`, `representative-strategy-without-omitted-combinations`, `representative-strategy-without-residual-risk` |
| R-TC-TYPE | type conflicts with expected result | Positive only for acceptance; validation/error oracle => Negative / Validation Negative | `tc-type-expected-result-mismatch` |
| R-TRACE-EXERCISED | trace names source fields/actions | traced behavior is exercised or explicitly supporting | `trace-not-exercised-by-steps` |
| R-ONE-ASSERTION | TC proves independent assertions | split dictionary/branch/action/persistence checks unless rationale applies | `multiple-independent-assertions-in-one-tc` |
| R-REP-DATA | strategy states selected classes | strategy and coverage matrix match concrete values/domains/classes | `representative-strategy-data-mismatch`, `sampled-field-group-without-group-strategy`, `coverage-matrix-tc-domain-mismatch` |
| R-NEG-TRIGGER | candidate-negative invalid input | include neutral completion/focus/validation/save trigger or trigger BA question | `candidate-negative-validation-trigger-missing`, `candidate-negative-trigger-too-specific` |
| R-PERSISTENCE-COVERAGE | editable CRUD/card scope | save/reopen smoke or rationale; save, reopen, verify; exercised trace; reproducible setup; grouped residual risk | `persist-coverage-missing-for-crud-scope`, `field-level-canary-without-persistence-scope-note`, `persistence-tc-without-save-action`, `persistence-tc-without-reopen-verification`, `persistence-tc-closes-without-saving`, `persistence-tc-unsourced-save-action`, `persistence-smoke-without-cleanup-strategy`, `persistence-trace-not-exercised`, `persistence-precondition-passive-state`, `persistence-delete-tc-not-self-contained`, `persistence-grouped-smoke-without-residual-risk` |
| R-CREATE-FORM-ISOLATION | source-backed `Создать` / `Добавить` opens a form for a new independent object, child record or row | plan a separate check: create A with distinctive user-entered values, open creation of B, and verify that B does not inherit A values; exclude source-defined defaults, inherited/context values, clone/import and documented draft restoration | writer gate `creation-form-isolation-coverage`; reviewer `creation-form-isolation-coverage-missing` |
| R-PERSISTENCE-CALIBRATION | persistence smoke has unconfirmed save/reopen/cleanup flow | keep candidate status, link BA/UI questions/package; block executable conversion until flow is confirmed; placeholders only in candidates | `persistence-candidate-without-calibration-questions`, `executable-persistence-with-unconfirmed-save-flow`, `persistence-save-placeholder-in-executable-tc`, `persistence-calibration-package-missing` |
| R-PERSISTENCE-TERMS | persistence contact-person relation term | use source-backed relation term or document mapping | `persistence-terminology-source-mismatch` |
| R-SOURCE-UI-TERMS | section UI block names | use source-backed term or document naming decision | `source-backed-ui-term-inconsistency` |

| R-CONCRETE-DATA | executable TC | concrete data or formula | `test-case-generic-test-data-reference-smell`, `test-case-generic-test-data-oracle-smell` |
| R-DATA-PROVENANCE | concrete domain value in setup/test data | classify provenance as source/support/mockup/UI literal, dictionary value, verified fixture, execution-relative formula, or neutral synthetic free-text value; source-bound values without provenance stay `needs-test-data` / `candidate-ui-calibration` / `GAP-*` | reviewer `test-data-provenance-missing`, `source-bound-synthetic-value`, `fixture-field-semantic-mapping-unsupported` |
| R-TITLE-METADATA | candidate/calibration/process status | keep process markers out of `Title`; put status in body metadata | `test-case-title-process-marker-smell` |
| R-PRODUCTION-MARKDOWN | production TC markdown | `## TC-*` and metadata fields start their own lines | `production-markdown-heading-not-at-line-start`, `production-metadata-field-not-at-line-start` |
| R-ORACLE-POLARITY | validation, requiredness, boundary or allowed-symbol TC | keep one dominant oracle polarity per TC; split positive allowed value, negative invalid value and recovery flow unless source explicitly defines one recovery scenario | `runtime-writer-mixed-polarity`, `tc-type-expected-result-mismatch`, reviewer `positive+negative merge` |
| R-INPUT-CLASS-DECOMPOSITION | source says only/exact allowed symbols, format, length or class | create separate source-derived classes such as valid representative, whitespace, alphabet/script class, special/disallowed symbols and boundary values; missing classes become narrow `GAP-*` / `candidate-ui-calibration`, not silent coverage | reviewer `numeric-only-class-gap`, `exact-length-class-gap`, `missing-equivalence-class` |
| R-PARAMETER-UI-LEVEL | parameter table rows use different start screens, UI levels, navigation paths or parent/child entities | split into separate `TC-*`; compactness must not reduce manual executability or automation-readiness | `parameterized-tc-crosses-ui-levels`, reviewer `non-atomic-parameterization` |
| R-ACTOR-OUTCOME-ATOMICITY | one TC switches actors/roles and asserts different visibility, permission or status outcomes | split by actor/outcome unless source explicitly defines one inseparable comparison view; each automated TC must have one account capability and one observable result | reviewer `multi-actor-outcome-merged`, `test-case-non-atomic-access-comparison` |
| R-UI-LABEL-FIDELITY | mockup or approved UI evidence names a visible tab, button, action or field | use that exact Russian label in runtime steps; a document section title is not a substitute for a visible UI label | reviewer `ui-label-not-evidence-backed` |
| R-STATUS-METADATA | TC has execution lifecycle state | use only `Статус исполнения`; explain unresolved data/oracle in `Требуется подтверждение`, without duplicate status aliases | reviewer `duplicate-execution-status-metadata` |
| R-UNSUPPORTED-OBSERVATION | implementation observation, exploratory UI discovery or integration not present in FT/support/evidence | record as exploratory note, gap or UI-calibration candidate; do not add FT-first baseline TC until the observation is registered as approved source/support/UI evidence | reviewer `derived-obligation-contamination`, `unsupported expected-result specificity` |
| R-PRIORITY-RISK | generated TC priority | assign priority from source-bound risk; requiredness, validation, closed dictionary, create/delete, integration, persistence, legal/financial data or blocking transition are high unless justified; simple visibility/editability is usually medium | reviewer `risk-model-too-flat`, `tc-priority-source-risk-mismatch` |
| R-EXECUTABLE-USEFULNESS | runtime TC is formally structured but has no concrete object/screen/action/oracle, delegates the main check to setup, references another TC's steps, or repeats the source rule as the expected result | rewrite as a self-contained executable TC with concrete object, place, action and observable result; otherwise keep an explicit non-executable status and `Требуется подтверждение` | reviewer `formally-valid-useless-tc`, `non-self-contained-steps`, `expected-result-restates-requirement`, `main-check-hidden-in-precondition` |
| R-BUSINESS-STATE-OBSERVABLE | source defines business state/status/lifecycle but UI/API/document exposes it through indicator, visibility, action availability, badge, field, generated output or another artifact | keep the business state in setup/test data, but expected result must verify the actual observable artifact; do not expect visible status text unless source/support/UI evidence says the text is displayed | reviewer `business-state-without-observable-artifact`, `status-text-assumed-without-evidence` |
| R-LIFECYCLE-EXECUTION-OWNERSHIP | status/lifecycle or glossary row is used to plan a TC | assign one concrete object, screen/card/list/block and user action that owns the observed behavior; if the source gives only a definition, retain it as supporting traceability and create a narrow `GAP-*`, not a generic availability TC | `status-lifecycle-execution-owner-missing`, reviewer `status-lifecycle-generic-owner` |
