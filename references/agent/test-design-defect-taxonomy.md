# Test Design Defect Taxonomy

This reference records recurring test-design defect classes that the agent must account for in later writer/reviewer iterations. If a new defect does not fit an existing class, add the new class here, then synchronize the validator, tests/evals, and skill instructions.

## Mandatory Classes

| defect_class | Symptom | Required action |
| --- | --- | --- |
| `unsupported-ui-mechanism` | A TC expects a concrete UI mechanism that is not present in the FT or approved materials: character does not appear, field clears itself, button is disabled, exact error text, auto-formatting. | Remove the unsupported mechanism from the expected result or record `GAP-*` / `unclear`. For numeric-only rules, verify acceptance/rejection of symbol classes, not the filtering mechanism, unless the source defines the mechanism. |
| `nondeterministic-alternative-oracle` | A negative TC allows several different reactions through `or`: value is cleared or not saved, character is rejected or field remains empty/previous, marker or no-change. | Choose one source/evidence-backed observable oracle. If the exact reaction is unknown, do not create an executable baseline TC; record a narrow `GAP-*` / `unclear`. |
| `executable-over-unresolved-mechanism` | A TC remains executable and claims pass/fail even though the key action method or UI feedback is explicitly left as `GAP-*` / unresolved mechanism. | Separate the source-backed invariant from the unresolved mechanism: cover only the executable part and keep the missing mechanism in `GAP-*`; if the action cannot be described without the gap, do not treat the TC as baseline executable. |
| `ambiguous-ui-alias-step` | A step contains several possible labels/actions through `/`, `alias`, `или`, for example `Click A / UI alias B`, leaving the executor unsure which control to use. | Keep one visible label from the FT/mockup inventory/approved material in the step; move the alias into source evidence, mockup usage, or a note. |
| `format-mask-not-covered-by-numeric` | A format mask is covered only by a “digits only” check or by a value without the visible pattern. | Create a separate `format-mask` obligation `mask-pattern-applied`; for a default mask, create `default-mask-visible`. Expected result must observably check the pattern/mask. |
| `numeric-only-class-gap` | A `digits only` rule is covered by one mixed invalid value or only a letter, without space, special symbol, decimal separator, and sign. | Create `numeric-format` obligations for valid digits, reject letters, reject spaces, reject special chars, reject decimal separator, reject sign; record non-testable classes as narrow `GAP-*`. |
| `exact-length-class-gap` | An exact-length rule covers only `N` and `N-1`, or a generic invalid length, but not `N+1`. | Create `exact-length` obligations: `exact-length-accepted`, `shorter-rejected`, `longer-rejected`; do not merge `N-1` and `N+1`. |
| `dictionary-closed-set-missing` | Source/support workbook defines a dictionary or fixed value list, but `dictionary-inventory.md` is absent/incomplete, or plan/TC checks only one value or does not check absence of extra values. | Extract values into `dictionary-inventory.md`, link `DICT-*`, and verify dictionary values plus closed-set behavior. If closed-set behavior does not follow from the FT, record `GAP-*` / `unclear`; do not assume it. |
| `action-created-optionality-gap` | Required fields inside a block created by an `Add ...` button are treated as if adding the block itself were mandatory; the no-action branch is missing. | Separate the action branch, requiredness of created-block fields, and optional no-action branch; if mandatory addition is not described, record `GAP-*`. |
| `repeatable-block-lifecycle-gap` | A repeatable block is covered only by first add/delete, without checking the second independent block, deleting one of several, deleting the last, or re-adding after delete. | Create repeatable-block lifecycle obligations and TC/GAP rows for first add, second independent add, delete one preserves others, delete last, and re-add after delete. |
| `checkbox-list-obligation-gap` | A checkbox/multi-select list is checked only as a dictionary of values, without checking requiredness, single selection, multiple selection, or deselection. | Create checkbox-list obligations; cover source-backed missing branches with TC and record disputed reset/preserve branches as `GAP-*`. |
| `print-form-content-mapping-gap` | A TC checks that a print form/document is generated and claims data mapping coverage without source-backed mapping. | Split `print-form-generated` and `print-form-content-mapping`; cover content mapping only from source or record `GAP-*`. |
| `negative-transition-without-valid-fixture` | A negative check through a transition/button such as `Следующий шаг` / `Продолжить` does not define a valid state for all other required fields. | Provide a named valid fixture or explicitly state that all other required fields are valid; otherwise failure attribution is unreliable. |
| `test-data-provenance-missing` | A concrete domain value is used in setup or test data without a clear provenance category: source/support/mockup/UI literal, dictionary value, verified fixture, execution-relative formula, or neutral synthetic value for unrestricted free text. | Classify provenance and cite the source/fixture/dictionary, or keep the TC as `needs-test-data`, `candidate-ui-calibration`, or a narrow `GAP-*`. |
| `source-bound-synthetic-value` | A plausible synthetic value is used for a source-bound field/object affected by integration, dictionary, search/filter, autofill, rights/status, backend mapping, or similar business logic. | Replace it with a verified fixture/source literal/dictionary value, or mark the check as blocked by missing test data/evidence. |
| `fixture-field-semantic-mapping-unsupported` | A field from a fixture or external source response is used as the expected value for a different semantic UI/FT field without explicit mapping evidence. | Keep the raw fixture field as evidence, but do not assert target UI field mapping until FT/support/UI evidence confirms the mapping; otherwise create a calibration/gap item. |
| `coverage-metrics-missing` | An applicable coverage dimension exists in the matrix/plan, but the writer did not count obligations/classes/branches/transitions and their covered/gap status. | Create `coverage-metrics.md` or a linked split artifact; do not send dimensions to review without measurable coverage state. |
| `risk-model-too-flat` | A high-risk atom has a priority without `impact x likelihood`, residual-risk decision, or explicit rationale; a low-frequency/high-impact case is downgraded. | Update `risk-priority-map.md` by `risk-priority-map-format.md`; do not downgrade high impact because of low frequency, and keep residual risk as a visible gap. |
| `applicability-linked-tc-drift` | `Test-design Applicability Matrix` marks a dimension as covered, but the linked `TC-*` actually verifies another dimension. | Check linked TC semantics: title, steps, data, and expected result must exercise the row dimension. Otherwise replace the linked TC or create `GAP-*`. |
| `false-gap` | TDDT/ledger/plan sends a requirement to `gap_unclear` or `GAP-*` even though the source already gives an observable UI/API outcome: hint, message, red highlight, confirmation, navigation, mask, dictionary/tags, date-window boundary, or another pass/fail oracle. | Reclassify the testable part as `standalone_tc` / `covered_by_existing_tc`; keep `GAP-*` only for the actually missing part. |
| `overbroad-gap` | One `GAP-*` mixes a testable part with a blocker such as missing fixture, dictionary, product catalog, backend artifact, status, or test clock. | Split into executable coverage and a narrow gap with exact `blocked_part`; update TDDT, Coverage Obligation Table, ledger, plan, and coverage gaps. |
| `metadata-only-behavior` | Source-backed behavior with a visible result is marked `metadata_only` because the writer treated the row as structural context. | Separate metadata from behavior: keep metadata non-executable and route behavior to TC coverage or a narrow `GAP-*`. |
| `date-window-gap` | Age/date windows with specified boundaries and hints, for example passport ages 14/20/45, are sent entirely to gap. | Decompose windows into boundary/equivalence obligations; `GAP-*` is allowed only for test clock, fixture, or disputed boundary convention. |
| `semantic-compression` | One atom/plan row/TC closes several independent system obligations that can pass/fail separately. | Split into separate rows/TC or explicitly record scenario/recovery rationale that does not replace atomic checks. |
| `traceability-placeholder` | `Ссылка на ФТ`, `Трассировка`, ledger, or matrix contains placeholder `-`, `N/A`, an empty id slot, or a fake id between real references. | Remove the fake item and keep only real `ATOM-*`, requirement code, `SRC-*`, section/table/page/source quote/`DICT-*`; if no id exists, trace explicitly to the source location without a placeholder. |
| `source-rule-oracle` | Expected result is replaced with `по правилу из источника`, `по правилу видимости из источника`, `согласно источнику`, `согласно ФТ`, or an equivalent phrase. | Replace it with a concrete observable oracle: field is shown/hidden, value is displayed/not saved, transition is available/blocked, list contains concrete values. |
| `generic-editability` | Editability TC uses steps such as `Активировать элемент` / `Изменить значение на тестовое значение`, two sample values without choosing one, or expected result without the literal new value. | Specify the initial and new value, the concrete action for the control type, and the expected result with the new displayed value; keep persistence as a separate TC. |
| `derived-obligation-contamination` | A test-design-derived check (`v2 obligation`, exploratory/risk-derived/regression check) is recorded as a normal source-backed `ATOM-*` without `source_or_rule_ref`, defect class, coverage dimension, or reviewer finding. | Explicitly mark derivation and link it to the source-backed obligation, or move it to a non-baseline exploratory/risk-derived check; do not present a derived check as a new FT row. |
| `derived-setup-behavior-as-source` | Setup/control behavior useful for another TC, for example clearing a checkbox-list to no-selection state, is recorded as a source-backed baseline requirement without explicit source or derivation. | Mark it as `test-design-derived` setup/recovery behavior and do not count it as separate source-backed coverage, or confirm the source and keep it as baseline TC. |
| `template-postcondition-noise` | Read-only/list-composition/visibility TC contains boilerplate `Вернуть измененные данные...` although steps do not modify data. | Replace it with `Не требуются` or a concrete cleanup action if the TC actually changes state. |
| `missing-equivalence-class` | Source-backed restriction says only/exact allowed values, symbols, length, format, or class, but the suite covers only a single representative or mixed invalid value and omits independently derivable classes such as whitespace, alphabet/script class, special symbols, `N-1`/`N+1`. | Split into explicit coverage obligations/TCs for each independently checkable class, or record a narrow class-specific `GAP-*` / `candidate-ui-calibration` when the UI reaction is unknown. |
| `unsupported-alphabet-assumption` | TC asserts Latin/Cyrillic/whitespace acceptance or rejection only from an implementation observation or writer assumption, while FT/source/support does not define that alphabet/script behavior. | Do not promote to FT-first baseline. Register source/support/UI evidence or convert to exploratory note, `GAP-*`, or UI-calibration candidate with a concrete question. |
| `tc-priority-source-risk-mismatch` | Priority is assigned as a flat default or contradicts source-bound risk: validation/requiredness/closed dictionary/create-delete/integration/persistence/legal-financial/blocking transition is medium/low without rationale, or simple visibility/editability is high without risk reason. | Update risk rationale and priority according to `risk-priority-map-format.md`; reviewer blocks only when priority weakens risk coverage or misleads execution focus. |

## Feedback Loop

1. Record the defect as a `finding` with a concrete `defect_class`, source evidence, and affected artifacts.
2. Update this taxonomy when the class is new or the current description is insufficient.
3. Add or extend a validator rule when the defect can be caught reliably by static analysis.
4. Add a regression test/eval candidate based on the real failure.
5. Update writer/reviewer instructions only by linking to the canonical reference; do not duplicate long rules.
6. Run `python scripts/run_tests.py` and `python scripts/run_tests.py --suite architecture`.

## Severity

- `error`: the defect makes sign-off unreliable: unsupported behavior, missed mandatory branch, incorrect matrix -> TC link, or missing valid fixture for a negative transition check.
- `warning`: the defect reduces completeness or diagnosability, but does not by itself make an already written TC false.
- `info`: structure or explicitness improvement that does not affect pass/fail.
