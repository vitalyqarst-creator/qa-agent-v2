# Компактная матрица тест-дизайна

Матрица — один файл `work/practical/<scope>/test-design-matrix.md`. Она нужна, чтобы до написания TC проверить покрытие и объединение однотипных проверок, а не чтобы создавать дополнительный маршрут.

## Обязательные колонки

| ID | Источник требования | Проверка | Предусловие/исходное состояние | Конкретные тестовые данные | Ожидаемый результат | Решение |
| --- | --- | --- | --- | --- | --- | --- |

- `Источник требования`: раздел, таблица/строка, код ФТ при наличии.
- `Проверка`: одно пользовательское действие и один основной оракул.
- `Конкретные тестовые данные`: буквальные значения или `Не требуются.`; внутренние ID fixtures допустимы только в дополнительной рабочей колонке, не вместо значений.
- `Решение`: `TC` или `coverage-gap`. Неразрешённая data/oracle-зависимость — только `coverage-gap`.

## Правила объединения и разделения

- Один выбор DaData-подсказки и проверка набора однотипных полей автозаполнения — одна строка/один TC, если поля заполняются одним действием и принадлежат одному результату интеграции.
- Одна операция открытия/отмены/сохранения — отдельная проверка, когда её результат независим.
- Валидацию с разными независимыми классами невалидности разделяй; набор эквивалентных значений того же поля параметризуй в одной строке.
- Не создавай строку ради одного кода ФТ, если код содержит несколько проверяемых утверждений.
- Не создавай строку без проверяемого UI-результата или конкретных данных.

## Результат review

Reviewer сверяет матрицу с первичными источниками и выносит только `matrix-accepted` либо `matrix-changes-required`. После одной ограниченной правки повторяет review; второй дополнительный цикл не запускается без решения пользователя.
