# Компактная матрица тест-дизайна

Матрица — один файл `work/practical/<scope>/test-design-matrix.md`. Она нужна, чтобы до написания TC проверить покрытие и объединение однотипных проверок, а не чтобы создавать дополнительный маршрут.

До создания matrix прочитай `references/runtime/test-design-profiles.md`.

## Обязательные колонки

| ID | Источник требования | Проверка | Профили тест-дизайна | Предусловие/исходное состояние | Конкретные тестовые данные | Ожидаемый результат | Решение |
| --- | --- | --- | --- | --- | --- | --- | --- |

- `Источник требования`: один или несколько `SR-*` из `source-row-inventory.md`, затем раздел, таблица/строка и код ФТ при наличии. `SR-*` не заменяет первичную трассировку.
- `Проверка`: одно пользовательское действие и один основной оракул.
- `Профили тест-дизайна`: применимые профили из `test-design-profiles.md`; минимум `базовый`.
- `Конкретные тестовые данные`: буквальные значения или `Не требуются.`; внутренние ID fixtures допустимы только в дополнительной рабочей колонке, не вместо значений.
- `Решение`: `TC` или `coverage-gap`. Неразрешённая data/oracle-зависимость — только `coverage-gap`.
- Для строки `coverage-gap` значение `ID` совпадает с `GAP-*` из `coverage-gaps.md`. Так пробел нельзя потерять между этапами.

## Правила объединения и разделения

- Решения об атомарности, параметризации, связанных результатах и независимых классах принимай только по `test-design-profiles.md`.
- Не создавай строку без проверяемого UI-результата или конкретных данных.
- Каждая активная обязанность из `source-row-inventory.md` должна присутствовать в матрице через свой `SR-*`. Несколько атомарных строк инвентаря допустимо объединить в одну строку матрицы только по правилам профилей тест-дизайна. Раздел применённых исключений не проецируется в матрицу. Пробел покрытия не удаляется: он остаётся строкой с решением `coverage-gap`.
- Перед review запусти `python scripts/validate_runtime_matrix.py <matrix> --source-inventory <source-row-inventory.md> --coverage-gaps <coverage-gaps.md>`.

## Результат review

Reviewer сверяет матрицу с первичными источниками и профилями тест-дизайна, затем выносит только `matrix-accepted` либо `matrix-changes-required`. Review-record связывается с SHA-256 matrix по `references/runtime/review-record.md`. После одной ограниченной правки повторяет review; второй дополнительный цикл не запускается без решения пользователя.
