# Контракт внешних зависимостей

Загружай этот файл только при непустом `external_reference_catalog` либо при позднем поступлении связанного внешнего источника.

## Классификация

Скопируй каждый `EXT-*` и его `source_anchor` в условную таблицу `external_references` публичного scope-контракта ровно один раз:

- `контекст` — справочная связь без самостоятельного результата: `Нет текущей обязанности`, без `SR-*`/`GAP-*`, статус `учтено` или `не-применимо`;
- `отложенное-правило` — внешний документ задаст неизвестную семантику: известную локальную часть сохрани отдельной `SR-*`, неизвестный остаток — отдельным `GAP-*`; если текущего результата нет, укажи `Нет текущей обязанности` без искусственного GAP;
- `внешняя-точка-наблюдения` — результат заявлен, но наблюдается только в другом UI/API: отдельные `SR-*` и GAP класса `нет-точки-наблюдения`;
- `подготовка-данных` — правило известно, отсутствует только актор, объект или состояние: `SR-*` и `test-data-plan`, без GAP.

Наличие тестового пользователя подтверждает лишь готовность данных и не заменяет отсутствующую ролевую семантику. Известную локальную обязанность нельзя скрывать внешней ссылкой.

Статусы: `ожидает-источник`, `частично-урегулировано`, `источник-получен`, `учтено`, `не-применимо`. Первые два явно фиксируют: `Не блокирует остальные проверки.` `источник-получен` означает регистрацию входа, но не его применение; `учтено` допустимо после reconciliation и закрытия связанных GAP.

Для ожидаемого источника с GAP добавь в общий реестр карточку `external_source_card` с полем `Целевой источник` и редактируемой строкой `Ответ БА`. Чистый контекст или ссылка без текущей обязанности остаётся только строкой `EXT-*`.

## Частичный выпуск

Внешний GAP переносится в matrix как `coverage-gap` / `blocked-observability`, но не блокирует принятие детерминированных строк и выпуск их TC. Не создавай TC на неизвестное правило. Controller называет выпуск `частичное покрытие с отложенными внешними источниками` и перечисляет открытые `EXT-*`/`GAP-*`.

## Поздний источник

1. Source locator регистрирует предоставленный документ, правило или evidence интерфейса как support через `--support-update`.
2. Analyzer читает новый support и только связанные `EXT/SR/GAP/CLR`, сохраняя остальные ID и `scope_revision_count`; это новый input, не correction прежней ошибки.
3. Writer сохраняет неизменённые `M/TD/REL/TC`, заменяет закрываемые GAP, добавляет новые строки и переводит matrix в `review-pending`.
4. Независимый matrix reviewer проверяет полный текущий hash. После принятия writer обновляет materialization и затронутые TC, добавляя новые номера в конец.
5. Полный TC-validator и независимый TC review проверяют актуальный набор. Несвязанные scope не запускаются; прежние review остаются историческими для прежних hashes.
