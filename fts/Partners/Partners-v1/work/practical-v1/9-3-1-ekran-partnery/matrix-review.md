## Findings

1. **Severity: error — SCN-001 неатомарно объединяет AS.3 и AS.4 и не доказывает отсутствие подразделов.**

   - **Source ref:** `SRC-01`, 9.3 `AS.3` («на вкладке, без деления на подразделы»); `SRC-02`, 9.3 `AS.4` (двухуровневая структура: карточка партнёра и реквизиты).
   - **Проблема:** результат «раздел открыт как вкладка, а реквизиты доступны внутри выбранного партнёра» не проверяет отсутствие подразделов и не проверяет отдельно наличие двух уровней. Оба утверждения могут иметь разные результаты выполнения.
   - **Точное исправление:** заменить `SCN-001` двумя строками: (а) отдельная проверка `AS.3` с наблюдаемым результатом «раздел “Партнёры” открыт как вкладка и в нём отсутствует деление на подразделы»; (б) отдельная проверка `AS.4` двух уровней — общего перечня карточек партнёров и реквизитов после открытия выбранного партнёра. Для каждой строки оставить только относящиеся к ней данные/состояние.

2. **Severity: error — SCN-002 не покрывает ограничение статусов для любой сущности блока.**

   - **Source ref:** `SRC-03`, 9.3.1 `AS.6` («любой сущности в блоке “Партнёры”»); `SCN-002`; `TDP-ENV-002`, `TDP-ENV-004`.
   - **Проблема:** строка сформулирована для неопределённой «сущности», а её данные содержат только состояния партнёра (`TDP-ENV-002`). Ограничение из `AS.6` применяется также к реквизитам; разрешённые lifecycle-строки не доказывают отсутствие иных переходов.
   - **Точное исправление:** разделить `SCN-002` на два `candidate-ui-calibration` intent: для партнёра с `TDP-ENV-002` и для реквизитов с `TDP-ENV-004`. В каждой строке сохранить конкретный вопрос о наблюдаемом способе установить отсутствие переходов, кроме «Подтверждён» ↔ «Скрыт»; не выводить набор кнопок из предположения.

3. **Severity: error — доступность команд при наведении склеена с результатом смены статуса.**

   - **Source ref:** `SRC-17`/`AS.12` и `SRC-19`/`AS.14`; `SRC-21`/`AS.16` и `SRC-23`/`AS.18`; `SRC-35`/`AS.26` и `SRC-37`/`AS.28`; `SRC-39`/`AS.30` и `SRC-41`/`AS.32`.
   - **Проблема:** `SCN-012`, `SCN-014`, `SCN-021` и `SCN-023` одновременно проверяют появление команды по наведению и изменение статуса/цвета. Команда может быть доступна при неисправном переходе, поэтому это независимые pass/fail решения.
   - **Точное исправление:** для каждой из четырёх строк выделить отдельный intent доступности команды при наведении и отдельный intent перехода из требуемого исходного статуса с проверкой изменения индикатора. Во второй строке не засчитывать доступность кнопки как её основной expected result.

4. **Severity: error — ролевые права на команды и видимость сущности после перехода смешаны; запрет для не-администратора не проверен.**

   - **Source ref:** `SRC-04`, 9.3.1 `AS.6`; `SRC-18`/`AS.13`, `SRC-20`/`AS.15`, `SRC-22`/`AS.17`, `SRC-24`/`AS.19`; `SRC-36`/`AS.27`, `SRC-38`/`AS.29`, `SRC-40`/`AS.31`, `SRC-42`/`AS.33`.
   - **Проблема:** `SCN-003` дублирует общий результат конкретных lifecycle-строк и не определяет тип сущности. `SCN-013`, `SCN-015`, `SCN-022` и `SCN-024` объединяют видимость/доступность команды с видимостью скрытой либо восстановленной сущности. Кроме того, строки с архивированием фиксируют видимость команды администратору, но не проверяют, что она недоступна другой роли, хотя `AS.6` назначает оба перехода только администратору.
   - **Точное исправление:** удалить `SCN-003` как дублирующий общий intent и добавить трассировку `SRC-04`/`AS.6` в объектные проверки переходов. Разделить каждую затронутую ролевую строку на: (а) проверку команды в требуемом стартовом статусе для администратора и другой роли; (б) отдельную проверку видимости скрытого объекта; (в) отдельную проверку видимости объекта после восстановления. Во всех проверках команд явно зафиксировать отсутствие команды/доступа у другой роли, а в проверках видимости — только соответствующее post-transition состояние.

5. **Severity: error — SCN-016 скрывает три независимые обязанности экрана реквизитов.**

   - **Source ref:** `SRC-25`/`AS.20`, `SRC-26`/`AS.21`, `SRC-27`/`AS.22`; `SCN-016`.
   - **Проблема:** наличие реквизитов после перехода, единственный допустимый столбец и корректность заголовка/счётчика могут независимо дать pass/fail. Текущий составной expected result не обеспечивает трассируемую атомарность.
   - **Точное исправление:** заменить `SCN-016` тремя строками: отображение реквизитов выбранного партнёра (`AS.20`); наличие только одного столбца «Реквизиты» (`AS.21`); отображение заголовка и числа, равного числу реквизитов подготовленного партнёра (`AS.22`).

6. **Severity: error — данные для SCN-011 не позволяют доказать, что открыт именно выбранный партнёр.**

   - **Source ref:** `SRC-16`, Таблица 3 `AS.11`; `SCN-011`; `TDP-ENV-004`; `FX-ENV-PARTNER-001`.
   - **Проблема:** `TDP-ENV-004` требует лишь партнёра, «в который можно перейти», но не его различимый идентификатор и не наблюдаемый признак на целевом экране. Поэтому формулировка «а не другой объект» не имеет воспроизводимой data/oracle основы.
   - **Точное исправление:** до materialization дополнить `TDP-ENV-004` и `FX-ENV-PARTNER-001` свойствами: различимый партнёр, его известное отображаемое имя или ID на карточке общего списка и тот же признак на открытом экране. Связать эти свойства с `SCN-011`; если целевой признак нельзя подтвердить ФТ/PDF/локальным макетом, перевести только этот intent в `candidate-ui-calibration` с точным вопросом о наблюдаемом oracle.
