# Handoff для UI-калибровки v3 — 9.3.2 «Карточка партнёра»

## Назначение и границы

Этот handoff предназначен для агента на ПК с доступом к тестовому стенду.
Он содержит только 15 тест-кейсов со статусом `candidate-ui-calibration` из
проверенного кандидата v3:

`test-cases/candidates/9.3.2-kartochka-partnera-v3.md`.

Baseline v2 и кандидат v3 изменять нельзя. Результат UI-прогона оформить
отдельным evidence-only commit в
`work/ui-automation-prep/9.3.2-kartochka-partnera-v3/`.

ФТ остаётся источником требований. UI-калибровка уточняет только фактический
trigger, шаги воспроизведения и наблюдаемый UI-oracle; она не отменяет
ожидание ФТ без отдельной пометки `mismatch-ft-ui`.

## Что нужно подтвердить до прогона

1. Runtime URL и способ входа в стенд.
2. Учётная запись, которой доступно создание и редактирование партнёра;
   конкретные логин, роль и пароль в evidence не сохранять.
3. Возможность подготовить две карточки:
   - `PARTNER-EDIT-001`: `ФОРМАД-ПЛАСТ ООО 7701`, ИНН `7733073764`, город
     `Санкт-Петербург`, доступна для редактирования;
   - `PARTNER-DUP-001`: `ПАО СБЕРБАНК`, ИНН `7707083893`, тип `Страховая
     компания`, юр. адрес `г Москва, ул Вавилова, д 19`.
4. В справочнике городов доступны `Санкт-Петербург` и `Уфа`.

Если любой пункт недоступен, не подбирать замену и не выдумывать данные:
зафиксировать соответствующий `blocked-access` или `blocked-ui-unavailable`.

## Общие правила evidence

- Перед действием снять свежий Playwright snapshot; после открытия карточки,
  смены фокуса, сохранения или закрытия снять новый snapshot.
- Для `confirmed` и `mismatch-ft-ui` сохранить screenshot нормального UI-пути.
- Для каждого TC записать: фактический trigger, введённое значение, наблюдаемую
  реакцию, итоговый статус и путь к evidence.
- Не считать DOM-only наблюдение подтверждением без обычного UI-действия.

## Критерий завершения

Для каждого из 15 TC зафиксирован один из статусов: `confirmed`,
`mismatch-ft-ui`, `blocked-access`, `blocked-ui-unavailable` или
`blocked-observability`. Для первых двух статусов приложен screenshot;
для неожиданной навигации или расхождения приложен trace.

После этого можно создать отдельную `automation-ready` версию кандидата v3,
не меняя baseline v2.
